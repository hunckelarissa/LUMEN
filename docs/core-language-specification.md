## 1. Цели ядра

Ядро языка должно быть:
- **минимальным** — только то, что необходимо для запуска прототипа;
- **расширяемым** — всё остальное добавляется модулями;
- **предсказуемым** — несмотря на метаморфность, поведение формализовано;
- **контекстно-чувствительным** — контекст влияет на интерпретацию операций;
- **реальным** — язык применим с первых версий.

## 2. Базовые сущности языка

### 2.1. Значения (Values)

| Тип | Описание |
|---|---|
| `Number` | Целые и вещественные числа (IEEE 754 double) |
| `String` | Unicode-строки |
| `Boolean` | `true` / `false` |
| `List` | Упорядоченная коллекция |
| `Map` | Ассоциативный массив (ключи-строки, только данные) |
| `Function` | Функция первого класса (замыкание) |
| `Morph` | Объект morph-блока (state + transforms + history) |
| `Context` | Объект окружения исполнения |
| `Null` | Отсутствие значения (`null`) |

### 2.2. Идентификаторы

Латинские буквы, цифры, подчёркивание. Первый символ — буква или `_`.
```
x, user_name, _foo42, myVar
```

### 2.3. Литералы
```
42, 3.14, -7                    # числа
"hello", "привет"               # строки
true, false                     # булевы
[1, 2, 3], []                   # списки
{name: "Lara", age: 30}, {}     # карты
null                            # null
```

## 3. Синтаксис ядра

Блоки явно открываются и закрываются ключевыми словами (`def...end`, `if...end`, `morph...end`). Отступы — только для читаемости, не несут семантической нагрузки. Комментарии — `#`.

### 3.1. Присваивание
```
x = 42
x = x + 1
```

### 3.2. Функции
```
def greet(name)
  print("Hello, ", name)
end
```
Функции — значения первого класса. Поддерживают замыкания.

### 3.3. Эволюция функций (when-dispatch)
```
def show(v)
  when Number then print("число: ", v)
  when String then print("строка: ", v)
  when List   then print("список из ", len(v), " элементов")
end
```
Ветви можно добавлять к уже определённой функции через повторный `def`.

### 3.4. Условные конструкции
```
if x > 10
  print("big")
elsif x > 0
  print("small")
else
  print("zero or negative")
end
```

### 3.5. Циклы
```
for item in range(10)
  if item == 5
    break
  end
  print(item)
end

while n < 100
  n = n + 1
  if n % 2 == 0
    continue
  end
  print(n)
end
```

### 3.6. Лямбда-функции
```
double = do |x| x * 2 end
print(double(5))   # → 10
```

## 4. Модель исполнения

### 4.1. Контекст
Каждый фрагмент кода исполняется в контексте, определяющем режим вывода и доступные модули. Контексты ядра: `cli` (по умолчанию), `test`.
```
context cli
  print("Running in CLI mode")
end
```

### 4.2. Трансформации типов
Типы переходят в другие типы по формальным правилам.

**Явная трансформация** (оператор `as`):
```
x = "42" as Number    # 42
y = 3.14 as String    # "3.14"
```

**Неявная трансформация** (через операторы, левый операнд определяет тип):
```
"42" + 1    # → 43 (String + Number → String as Number + Number)
42 + "!"    # → "42!" (Number + String → Number as String + String)
```

### 4.3. Проверка типа
```
if x is Number
  print("это число")
end
print(type(x))    # → "Number"
```

### 4.4. Живые структуры (Map)
```
user = {name: "Lara"}
user.age = 30
user.tags = ["dev"]
remove age from user
print(user.age)   # → null
```

## 5. Morph-блок — эволюция состояния

Центральная абстракция метаморфной парадигмы. Языковая конструкция (не библиотека).

### 5.1. Синтаксис
```
morph имя
  state поле: Тип = значение_по_умолчанию

  transform "имя_шага"
    skip if условие
    тело
  end
end
```

### 5.2. Семантика
- `morph` создаёт объект типа `Morph` с именованным состоянием и цепочкой transform-шагов.
- `state` — объявление поля в живой структуре morph-объекта.
- `transform "имя"` — именованный шаг. Выполняется при вызове `.run()`.
- `skip if условие` — условный пропуск шага.
- `require условие` — предусловие шага. Ложное условие прерывает `.run()` с `MorphError`, тело шага не выполняется. Пропущенный через `skip if` шаг свои `require` не проверяет.
- `.run()` — запускает все шаги последовательно.
- `.history` — журнал выполненных трансформаций. В ядре v0.1 запись содержит как минимум имя шага и статус. Целевая семантика (после v0.1) — полная интроспекция и кольцевой буфер; см. `docs/lumen_spec.md` §3.6a.5 и §3.6a.8.
- `.state` — текущее состояние (Map).
- Вложенный `morph` объявляется в теле родителя. Состояние общее: сначала поля родителя, затем ребёнка. `parent.run()` выполняет шаги родителя, затем детей, и дописывает их историю к своей.
- `left ~= right` истинно, когда истории двух morph совпадают по `step`, `status` и `message`.
- `dissonance strict|soft|creative ... end` выбирает режим явного `as`. По умолчанию `strict`.

### 5.3. Пример
```
morph counter
  state value: Number = 0

  transform "increment"
    state.value = state.value + 1
  end

  transform "double"
    state.value = state.value * 2
  end
end

counter.run()
print(counter.state.value)   # → 2
print(counter.history)       # → [{step: "increment", status: "ok"}, ...]
```

## 7. Ошибки

| Тип | Описание |
|---|---|
| `SyntaxError` | Ошибка разбора |
| `NameError` | Имя не найдено |
| `TypeError` | Операция неприменима к типу |
| `TransformError` | Невозможна трансформация типа |
| `ArithmeticError` | Деление на ноль |
| `IndexError` | Выход за пределы списка |
| `CallError` | Неверное число аргументов |
| `DispatchError` | Нет подходящей when-ветви |
| `ContextError` | Операция недопустима в контексте |
| `MorphError` | Ошибка в morph-блоке |

## 8. Граница прототипа 0.0.4

В коде уже есть вложенные morph, `require`, `~=` и диссонанс. Подробности — в `docs/lumen_spec.md`.

В прототип не входят:
- Модульная система (`import`)
- Исключения (`try/catch`)
- Многопоточность, JIT, оптимизатор
- Кольцевая история, значение сущности на каждом шаге, `self`
- `become`, `grow`, `extend` (слова зарезервированы)
- Автогенерация `llms.txt` (отложена вместе с LLM-спецификой)

## 9. Заключение

Эта спецификация определяет минимальное ядро LUMEN, включая morph-блоки как центральную абстракцию метаморфной парадигмы. Полная формализованная грамматика (EBNF), таблицы трансформаций и семантические правила — в `docs/lumen_spec.md`.
