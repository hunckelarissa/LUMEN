1. Техническое Задание на разработку языка программирования LUMEN
Название проекта: Разработка языка программирования LUMEN (метаморфная парадигма)
Заказчик/Автор: Лариса
Цель проекта: Создать новый реальный, документированный, кроссплатформенный язык программирования с уникальной метаморфной парадигмой, который позволит пользователям самовыражаться через код, а также послужит личным брендом автора как транс-женщины-разработчицы.
Срок реализации первой версии (MVP): 3–6 месяцев (ориентировочно)
Ключевые требования к результату:

Язык должен быть реальным, а не эзотерическим/игрушечным (не INTERCAL).
Минимальное ядро + расширяемость (как у токипоны / Lua).
Кроссплатформенность: Linux, Windows (в перспективе macOS, WebAssembly).
Две реализации: интерпретатор (прототип) + транспилятор в C.
Полноценная документация с туториалом «10 минут и ты пишешь код».
Открытый репозиторий с CONTRIBUTING.md и Code of Conduct.
Уникальная фишка — метаморфная парадигма (см. ниже).

Основная концепция (метаморфная парадигма):

Типы — не фиксированные метки, а состояния, между которыми возможны переходы (type transitions).
Функции могут эволюционировать — добавлять новые правила поведения для разных типов/контекстов.
Объекты/структуры — живые, могут менять форму (добавлять/убирать поля динамически, но контролируемо).
Контекст — первоклассная сущность, влияющая на семантику операций (CLI/GUI/web/тест и т.д.).

Требования к MVP (v0.1):

Синтаксис минималистичный, вдохновлённый Python/Ruby/Lua (без скобочного ада Lisp).
Базовые типы: Number, String, Boolean, List, Map, Function.
Поддержка переходов типов (пример: "42" + 1 → 43).
Многоформные/эволюционирующие функции (if Type: ...).
Динамическое расширение объектов (user.age = 30).
Простой контекст (print ведёт себя по-разному в разных окружениях).
REPL + CLI (run, compile, fmt).
Тесты + golden tests.
Документация: быстрый старт, философия, примеры.

Технологический стек (рекомендуемый):

Прототип: Python (Lark/ANTLR → AST → интерпретатор).
Транспилятор: генерация C-кода + минимальный рантайм на C.
Тестирование: pytest + golden tests.
Документация: Markdown + mkdocs.
Репозиторий: GitHub.

Критерии приёмки MVP:

Программа из 20–30 строк с использованием всех четырёх аспектов метаморфной парадигмы выполняется корректно.
REPL работает, print адаптируется к контексту.
Код компилируется в бинарник через gcc/clang.
Документация позволяет новичку написать и запустить программу за 10–15 минут.
Нет критических багов в ядре (покрытие тестов ≥70%).

2. Формализованная Спецификация ядра языка LUMEN (версия 0.1 — ядро)
1. Область применения
Язык общего назначения с акцентом на выразительность, гибкость и эксперименты.
2. Синтаксические категории (EBNF-подобное описание, упрощённое)
program         ::= { statement }

statement       ::= var_decl | func_def | expr_stmt | print_stmt | assign

var_decl        ::= identifier "=" expr
func_def        ::= "def" identifier "(" [params] ")" ":" { rule }
rule            ::= "if" type_pattern ":" block
type_pattern    ::= "Number" | "String" | "List" | identifier | ...
assign          ::= expr "=" expr
print_stmt      ::= "print" "(" expr ")"

expr            ::= literal | identifier | expr binop expr | call | dict | list
binop           ::= "+" | "-" | "*" | ...
literal         ::= number | string | "true" | "false" | list | dict
dict            ::= "{" [ pair { "," pair } ] "}"
pair            ::= identifier ":" expr
3. Семантика ядра
3.1. Переходы типов (Type Transitions)

Операции определяют требуемый контекстный тип.
Если фактический тип не совпадает, запускается переход (если разрешён).
Примеры разрешённых переходов: String → Number (при арифметике), Number → String (при конкатенации).

3.2. Эволюция функций

Функция — множество правил (rules).
При вызове ищется первое подходящее правило (по типу аргумента).
Правила можно добавлять динамически (в будущем — через синтаксис extend).

3.3. Живые структуры (Living structures)

Объекты начинаются как map-like.
Присваивание несуществующему ключу → добавление поля.
Тип объекта — динамический, но может быть аннотирован.

3.4. Контекстная адаптация

Глобальный/локальный контекст (CLI, Web, Test, GUI...).
Встроенные функции (print, read, ...) диспетчеризуются по контексту.

4. Встроенные типы и операции

Number: +, -, *, /, сравнения
String: +, len, []
List: append, len, []
Map: [], keys, values

5. Ошибки и исключения (MVP)

Только базовые runtime-ошибки (TypeError, NameError).

6. Расширяемость

Модули (import) — в v0.2+
FFI к C — в v0.3+
