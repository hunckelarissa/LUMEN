Полная формальная спецификация языка LUMEN
Версия 0.1 (ядро)
Дата: 12 марта 2026
Автор: Лариса (на основе метаморфной парадигмы)
1. Введение
LUMEN — язык программирования общего назначения, построенный на метаморфной парадигме.
Код рассматривается как живая структура, способная трансформироваться, эволюционировать и адаптироваться.
Ключевые принципы метаморфной парадигмы:

Типы — не фиксированные метки, а состояния на пути перехода (type transitions).
Функции — эволюционирующие сущности: поведение добавляется новыми правилами.
Объекты (структуры) — живые: могут менять форму в процессе выполнения.
Контекст — первоклассная сущность: одна и та же конструкция ведёт себя по-разному в зависимости от окружения (CLI, GUI, Web, Test и т.д.).

Синтаксис блоков: Ruby-style (явные end). Отступы не имеют семантического значения — они только для читаемости. Все блоки завершаются ключевым словом end.
Цель ядра: минимальное, но полностью работоспособное подмножество, достаточное для запуска прототипа и транспилятора в C.
2. Лексические соглашения

Идентификаторы: буквы (a-z, A-Z, включая юникод), цифры, подчёркивание. Первый символ — буква или _.
Ключевые слова:def, if, else, for, in, end, print, true, false.
Литералы:
Числа: 42, 3.14, -7
Строки: "hello", 'привет' (двойные и одинарные)
Списки: [1, 2, 3]
Карты (словари): {name: "Lara", age: 30}

Комментарии:# до конца строки

3. Синтаксис (EBNF-подобное описание)
program     ::= { statement }

statement   ::= var_decl
             |  func_def
             |  if_stmt
             |  for_stmt
             |  assign_stmt
             |  print_stmt
             |  expr_stmt

var_decl    ::= identifier "=" expr

func_def    ::= "def" identifier "(" [ param_list ] ")" block

block       ::= statement* "end"

if_stmt     ::= "if" expr block
             |  "if" expr block "else" block

for_stmt    ::= "for" identifier "in" expr block

assign_stmt ::= expr "=" expr

print_stmt  ::= "print" "(" expr ")"

expr        ::= literal
             |  identifier
             |  expr binop expr
             |  expr "(" [ arg_list ] ")"
             |  list_literal
             |  map_literal

binop       ::= "+" | "-" | "*" | "/" | "==" | "!=" | "<" | ">" | "<=" | ">=" | "+="

literal     ::= number | string | "true" | "false"
list_literal::= "[" [ expr { "," expr } ] "]"
map_literal ::= "{" [ pair { "," pair } ] "}"
pair        ::= identifier ":" expr
4. Семантика ядра
4.1. Переходы типов (Type Transitions)
Типы могут переходить автоматически по формальным правилам, когда операция требует другого типа.
Разрешённые переходы в ядре:

String → Number (если строка содержит корректное число)
Number → String (при конкатенации)
Number → Boolean (0 → false, иначе true)
List ↔ Map (ограниченно)

Пример:
x = "42"
y = x + 1          # "42" автоматически переходит в число → y = 43
4.2. Эволюция функций
Функция — множество правил. При вызове выбирается первое подходящее правило по типу первого аргумента (и контексту).
Синтаксис:
def show(v)
  if Number
    print("number: " + v)
  end
  if String
    print("string: " + v)
  end
  if List
    print("list of " + len(v) + " items")
  end
end
Правила можно добавлять динамически в будущем (v0.2+).
4.3. Живые структуры (Living Structures)
Объекты типа Map могут динамически менять форму:
user = {name: "Lara"}
user.age = 30          # поле добавляется
user.tags = ["dev"]    # новое поле
Тип объекта остаётся динамическим, но может быть аннотирован в будущем.
4.4. Контекстная адаптация
Контекст — неявный объект, доступный всему коду. Встроенные операции (print, read и т.д.) диспетчеризуются по текущему контексту.
Встроенные контексты ядра:

CLI (по умолчанию) — вывод в консоль
Test — запись в лог
(GUI и Web — в v0.2+)

Пример:
print("Hello")   # в CLI → консоль, в Test → файл лога
5. Встроенные типы и операции
Number
+ - * / == != < > <= >=
String
+ (конкатенация), len(s), s[i]
List
+ (append), len(l), l[i]
Map
m[key], m[key] = value (автоматическое добавление поля)
Boolean
true, false
Function
Функции первого класса, могут передаваться и возвращаться.
6. Модель исполнения

Интерпретатор/транспилятор выполняет AST последовательно.
Каждый вызов функции и операция проверяет текущий контекст.
Переходы типов происходят перед выполнением операции (lazy coercion).
Ошибки: только runtime-ошибки (TypeError, NameError, ContextError).

7. Ошибки и исключения (ядро)

TypeError — невозможный переход типа
NameError — неизвестный идентификатор
ContextError — операция не поддерживается в текущем контексте

Исключения (try/rescue) — в v0.2+.
8. Минимальный рантайм

Система типов с таблицей коэрций
Диспетчер правил для функций
Контекстный объект (глобальный + локальный)
Базовые примитивы (print, len, type)

9. Ограничения ядра (v0.1)

Нет модулей (import)
Нет классов
Нет многопоточности
Нет JIT
Нет FFI

Все расширения добавляются в последующих версиях без нарушения совместимости ядра.
10. Примеры программ (официальные)
Пример 1. Полная демонстрация парадигмы
x = "42"
y = x + 1
print("y = " + y)          # 43

def show(v)
  if Number
    print("number: " + v)
  end
  if String
    print("string: " + v)
  end
  if List
    print("list of " + len(v) + " items")
  end
end

user = {name: "Lara"}
user.age = 30
user.tags = ["dev", "creator"]

show(user.name)
show(user.tags)
Пример 2. Контекстная адаптация
print("Hello, LUMEN!")   # поведение зависит от контекста запуска

Любое расширение языка обязано сохранять совместимость с описанными правилами переходов типов, эволюции функций, живых структур и контекстной адаптации.
